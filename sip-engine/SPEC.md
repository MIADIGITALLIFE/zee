# SIP HTML Engine V1.0 — 工程规范（离线原型）

- 文档状态：工程基线草案
- 运行方式：静态 HTML / 浏览器本地运行
- AI 模型：不连接
- 网络依赖：核心页面不需要外部 CDN、API 或服务端
- 验证状态：代码已提交到功能分支后，仍需在真实浏览器执行测试；不能仅凭代码存在宣称 VERIFIED

## 1. 产品目标

构建一个可在浏览器中运行的离线原型，验证配置管理、多体系权重、确定性关联候选、主动任务状态模拟、JSON 导入导出与审计日志。这里的“主动”是规则驱动的程序行为，不表示主观意识或感知。

## 2. V1.0 范围

### 包含
1. 配置档案字段校验与 localStorage 保存/载入。
2. 四个示例体系的权重编辑与总和归一化。
3. 由目标关键词与权重生成可解释的交叉关联候选。
4. 由手动、事件、目标变化或定时模拟触发任务；任务状态为 pending、awaiting_confirmation 或 blocked。
5. JSON 导出、导入前结构检查与权重总和检查。
6. 会话内审计日志及日志导出。
7. 响应式布局、键盘焦点提示和减少动画偏好。

### 不包含
- 模型推理或“意识”声明。
- 浏览器关闭后的后台计划任务。
- 云同步、账号系统或数据库写入。
- 自动执行外部操作、自动发布或修改核心规则。
- 对真实世界事实的验证。

## 3. 组件与数据流

- UI：HTML 表单、参数滑块、结果列表、状态提示。
- 配置：profile = { name, goal, risk, initiative }。
- 系统：reasoning、memory、creative、safety。
- 权重：四项非负整数，合计必须为 100。
- 规则分析：命中目标关键词的次数与权重组成候选分；结果是启发式排序，不是模型推理。
- 任务模拟：输入触发类型、任务标题、优先级；输出模拟状态与解释。
- 存储：localStorage 保存当前 profile；任务与审计日志仅在当前页面会话内保留。
- 导入导出：JSON schema_version 固定为 1.0；导入时检查 profile、systems、weights 和权重总和。

## 4. 状态与证据

| 状态 | 定义 |
|---|---|
| DESIGNED | 已写入规范，尚不代表代码存在 |
| IMPLEMENTED | 代码存在，但尚未证明行为正确 |
| TESTED | 已在指定环境执行测试并记录结果 |
| VERIFIED | 测试有可复现证据且通过 |
| BLOCKED | 环境、依赖或信息缺失导致无法验证 |

当前交付只可标记为“原型代码已提交，待浏览器验证”。在没有测试运行记录前，所有运行时行为均不得标记 VERIFIED。

## 5. 建议验收测试

1. 页面可加载，无控制台错误。
2. 档案保存后刷新页面，载入数据一致。
3. 空档案名称被拒绝。
4. 风险与主动程度只接受 0–100 整数。
5. 权重调整后合计始终为 100。
6. 交叉分析会显示候选名称、分数与关键词命中依据。
7. 空任务标题被拒绝。
8. 任务模拟显示触发来源、优先级、状态与时间。
9. 导出文件是有效 JSON。
10. 导出的 JSON 可以重新导入且档案和权重一致。
11. 缺少字段或错误 schema_version 的 JSON 被拒绝。
12. 权重不合计 100 的 JSON 被拒绝。
13. 导入异常会显示错误，不应静默成功。
14. 宽屏和窄屏布局可用。
15. 无网络连接时核心页面仍可操作。

测试结果应逐项记录 PASS / FAIL / BLOCKED、浏览器与版本、日期、证据和缺陷编号。

## 6. 安全与隐私

- 不将 API key、service-role key 或其他秘密放入静态 HTML。
- 不通过 fetch/XHR 发送本地配置。
- 用户输入用 textContent 展示，避免把用户输入直接解释为 HTML。
- localStorage 是当前浏览器本地存储，不等同于加密保险库；共享设备应谨慎保存敏感数据。
- JSON 导入只接受预期结构，不自动执行导入文件中的代码。

## 8. 已知限制

当前实现为单页原型，尚未通过自动化浏览器测试。localStorage 与会话日志不提供跨设备同步或强持久化保证。交叉分析是透明的关键词/权重启发式规则，任务流转只是模拟。
